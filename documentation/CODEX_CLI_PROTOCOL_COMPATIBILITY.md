Date: 2026-07-15

## Current Baseline

- Installed CLI: `codex-cli 0.144.4`.
- NPM `@openai/codex` dist-tags checked on 2026-07-15: `latest` is `0.144.4`; `alpha` is `0.145.0-alpha.12`.
- Protocol artifacts in `documentation/app-server-schemas/` were regenerated from the installed `0.144.4` CLI with `codex app-server generate-json-schema --experimental` and `codex app-server generate-ts --experimental`.
- Official reference used for behavioral details: `openai/codex` `codex-rs/app-server/README.md`, `codex-rs/app-server-protocol/src/protocol/common.rs`, and `codex-rs/app-server-protocol/src/protocol/v2/thread.rs`.

## Compatibility Fixes Applied

1. Thread item pagination RPC changed.

   The old `thread/turns/items/list` schema is no longer generated by the latest stable CLI. The current schema exposes `thread/items/list`.

   Integration:
   - `src/api/appServerDtos.ts` now imports `ThreadItemsListResponse`.
   - `src/api/codexGateway.ts` calls `thread/items/list` first.
   - A runtime fallback still calls `thread/turns/items/list` if the new method is unavailable, preserving compatibility with older app-server builds.

2. `thread/turns/list` full item loading changed.

   Official app-server documentation says paginated `thread/turns/list` supports `summary` and `notLoaded`; `full` can fail and complete items should be paged with `thread/items/list`.

   Integration:
   - `src/api/codexGateway.ts` now requests `itemsView: "summary"` from `thread/turns/list`.
   - It then hydrates each turn with `thread/items/list`.
   - If item pagination is unavailable, the UI keeps the summary turn instead of failing the thread load.

3. Stable/main response-shape drift is tolerated.

   The `0.144.4` generated schema exposes `ThreadItemsListResponse.data` as `ThreadItem[]`. Current official main has moved toward `{ turnId, item }[]`.

   Integration:
   - `src/api/codexGateway.ts` accepts both response shapes when reading item pages.

## Newly Exposed Protocol Surface

The regenerated schema now exposes 122 client request methods and 68 server notification methods.

New or notably changed surfaces that are present in schema but not fully surfaced in the UI include:

- `environment/info` and `EnvironmentShellInfo`.
- `thread/items/list` as the replacement for per-turn item pagination.
- Additional thread metadata types such as `ThreadExtra` and `ThreadHistoryMode`.
- New item variants or response items including image generation and web search.
- Expanded plugin install policy/source metadata.
- Expanded rate-limit reset credit metadata and statuses.
- MCP startup failure reason metadata.
- Model requirement/default metadata such as `ModelsRequirements` and `NewThreadModelDefaults`.
